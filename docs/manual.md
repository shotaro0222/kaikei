# かいけい帳 運用マニュアル

個人事業の記帳から確定申告までを「かいけい帳」で行うための手順書です。
日々の作業・毎月の作業・年末から確定申告までの作業、システムの管理方法を、作業の流れに沿ってまとめています。

## 1. 全体像とスケジュール

### 年間スケジュール

| 時期 | 作業 | 画面 |
| --- | --- | --- |
| 毎日〜毎週 | 支出・売上を入力、領収書をアップロード | かんたん入力／領収書・請求書 |
| 毎月初 | 前月の銀行・カード明細を取り込んで仕訳、残高照合 | 銀行・カード明細／帳簿・レポート |
| 1月 | 当年分の定期的な支出（家賃・通信費など）を12か月分まとめて登録 | 仕訳帳／かんたん入力 |
| 12月末〜1月 | 決算整理（減価償却・家事按分・棚卸） | 決算整理 |
| 2月16日〜3月15日 | 所得税の確定申告（e-Tax） | 確定申告書類 |
| 〜3月31日 | 消費税の申告（課税事業者のみ） | 確定申告書類 → 消費税 |
| 申告後 | 翌年への繰越 | 決算整理 |

### 画面の構成（左メニュー）

| メニュー | 用途 |
| --- | --- |
| ホーム | 売上・経費・所得・所得税見込み、やることリスト |
| かんたん入力 | 「何に使ったか」を入力して自動仕訳 |
| 銀行・カード明細 | CSV取込・API同期した明細の仕訳 |
| 領収書・請求書 | 電子書類の保存・検索・仕訳との紐付け |
| 仕訳帳 | 全仕訳の確認・修正・複製・振替伝票入力 |
| 自動仕訳ルール | キーワード→勘定科目のルール管理 |
| 家事按分 | 按分割合の設定 |
| 固定資産台帳 | 減価償却する資産の登録 |
| 帳簿・レポート | 残高試算表・総勘定元帳・月次推移 |
| 決算整理 | 年末の決算整理仕訳・翌年繰越 |
| 確定申告書類 | 青色申告決算書／収支内訳書・申告書第一表・消費税 |
| 事業者設定 | 事業者情報・申告区分・勘定科目・期首残高・データ出力 |

画面右上の **年度選択**（例：2026年分）で、表示・集計する年を切り替えます。

## 2. はじめに一度だけ行う設定

### 2-1. 事業者情報と申告区分
**事業者設定 → 事業者情報・申告区分**

| 項目 | 入力内容 |
| --- | --- |
| 氏名・フリガナ・屋号・住所・事業所所在地・電話番号・業種名 | 決算書のヘッダに印字されます |
| インボイス登録番号 | 登録している場合のみ（T＋13桁） |
| 所得税の申告 | 青色申告（青色申告承認申請書を提出済み）／白色申告 |
| 青色申告特別控除 | e-Taxで提出するなら **65万円**、紙で提出なら55万円、簡易簿記なら10万円 |
| 消費税 | 免税事業者／2割特例／簡易課税（事業区分も選択）／本則課税 |
| AIによる自動仕訳の補助 | 通常は「使う」 |

> **消費税の区分の目安**
> - インボイス登録をしておらず、2年前の売上が1,000万円以下 → **免税事業者**
> - インボイス登録をした元免税事業者（2026年分まで） → **2割特例** が有利なことが多い
> - 簡易課税制度選択届出書を出している → **簡易課税**

### 2-2. 期首残高
**事業者設定 → 期首残高**

その年の1月1日時点の残高を入力します。

- **開業した年**：事業用口座の残高、事業用の現金、事業に持ち込んだ資産を入力します。
- **途中から本アプリを使い始めた年**：前年末の貸借対照表（前年の決算書4ページ目）の期末の金額を入力します。
- **元入金** の「自動」を押すと「資産 − 負債」で計算されます。資産合計と負債・資本合計が一致すれば完了です。
- 2年目以降は [翌年への繰越](#11-翌年への繰越) で自動作成されるので、入力は不要です。

### 2-3. 口座・カードの登録
**銀行・カード明細 → ＋口座・カードを追加**

事業で使う銀行口座・クレジットカード・電子マネーを登録します。

| 種類 | 対応する勘定科目（自動） |
| --- | --- |
| 銀行口座 | 普通預金 |
| クレジットカード | 未払金 |
| 現金 | 現金 |

> 銀行口座を複数使う場合は、事業者設定 → 勘定科目で「普通預金（〇〇銀行）」のような科目を追加し、口座ごとに割り当てると残高照合がしやすくなります。

### 2-4. 家事按分の設定
自宅兼事務所の家賃・光熱費・スマホ代などがある場合は、[7. 家事按分](#7-家事按分) を参照して設定します。

### 2-5. 定期的な支出の一括登録
毎月同じ金額の支出（家賃・サーバー代・サブスクなど）は、年初に12か月分をまとめて登録しておくと便利です（[4-1](#4-1-毎月同じ仕訳を登録する)）。

## 3. 日々の記帳

### 3-1. かんたん入力（基本）
**かんたん入力**

1. **支出（経費）／収入（売上）** を選択
2. **日付** と **金額（税込）** を入力
3. **何に使った？** に内容を入力（例：「Amazon でプリンターのインク」「電気代」「〇〇株式会社 Web制作費」）
4. **支払方法** を選択

   | 支払方法 | いつ使う | 仕訳の相手科目 |
   | --- | --- | --- |
   | 現金 | 事業用の現金で払った | 現金 |
   | 事業用口座 | 振込・口座振替・デビット | 普通預金 |
   | クレジットカード | カード払い | 未払金 |
   | 個人のお金 | プライベートの財布・口座で立て替えた | 事業主借 |

   収入の場合は「口座に入金」「現金で受取」「未入金（請求済み）」「個人口座に入金」から選びます。
5. 右側の **仕訳プレビュー** で勘定科目・税区分を確認します。違っていれば選び直してください。
6. 必要に応じて **取引先**・**メモ**・**領収書ファイル** を添えて **登録する** を押します。

推定の根拠はプレビュー下のラベルで分かります。

| ラベル | 意味 |
| --- | --- |
| 学習 | 過去に登録した同じ内容から判定（最も確実） |
| ルール | 自動仕訳ルールに一致 |
| 辞書 | 組込みのキーワード辞書から判定 |
| AI | AIによる推定（念のため確認推奨） |
| 仮 | 判定できなかった（必ず科目を選び直す） |

**一度登録した内容は学習され、次回から同じ内容は同じ科目で自動仕訳されます。** 最初の数週間は確認が必要ですが、使うほど手間が減ります。

### 3-2. 売上の記帳（請求 → 入金）
請求書を発行して後日入金される取引は、2回に分けて記帳します。

1. **請求したとき**：かんたん入力 → 収入 → 受取方法「**未入金（請求済み）**」
   → 仕訳：`売掛金 / 売上高`
2. **入金されたとき**：銀行明細の入金を仕訳するときに、勘定科目に **売掛金** を選ぶ
   → 仕訳：`普通預金 / 売掛金`

> 報酬から **源泉所得税が差し引かれて入金** された場合（例：報酬100,000円＋消費税10,000円＝請求110,000円、源泉所得税10,210円、入金99,790円）は、仕訳帳の振替伝票で次のように入力します。
> `普通預金 99,790 ／ 売掛金 110,000`
> `事業主貸 10,210 ／`
> 差し引かれた源泉所得税は年末に **確定申告書類 → 申告書 第一表 → 源泉徴収税額** にも入力します（支払調書の金額と照合）。

### 3-3. 私的な支出・入金
- 事業用口座から生活費を引き出した／私的な買い物をした → 勘定科目 **事業主貸**
- 個人のお金を事業用口座に入れた → 勘定科目 **事業主借**

国民健康保険・国民年金・所得税・住民税は経費になりません。事業用口座から払った場合は **事業主貸** で記帳し、社会保険料は申告時に **社会保険料控除** として入力します。

### 3-4. 仕訳の修正・削除
**仕訳帳** で行をクリックすると編集画面が開きます。

- 修正・削除の履歴は自動で記録されます（電子帳簿保存法対応）。履歴は編集画面の「訂正・削除履歴を表示」で確認できます。
- 銀行明細から作った仕訳を削除すると、その明細は「未処理」に戻ります。
- 「減価償却」「家事按分」「棚卸」のラベルが付いた仕訳は決算整理で自動作成されたものです。直接編集せず、決算整理画面で再作成してください。

### 3-5. 振替伝票（複雑な仕訳）
**仕訳帳 → ＋振替伝票で入力**

かんたん入力で表現できない仕訳（源泉税の差引入金、複数科目への分割、口座間の資金移動など）に使います。借方・貸方の合計が一致すると保存できます。

## 4. 毎月の作業

### 4-1. 毎月同じ仕訳を登録する
**方法A：まとめて先に登録（年初におすすめ）**

1. かんたん入力、または仕訳帳の振替伝票で1件目を入力
2. **「毎月繰り返し登録する」** にチェックを入れ、月数（2〜12か月）を選択
3. 「2026-01-25 〜 2026-12-25 の毎月25日に 12件 登録します」の表示を確認して登録

日付のルール：
- 月末日（1/31など）から始めると、毎月末日（2/28、3/31…）になります。
- 30日・31日がない月は、その月の末日になります。

**方法B：前月分をコピー**

1. 仕訳帳で前月の仕訳の行の **「複製」** を押す（編集画面の「コピーして新規作成」でも可）
2. 日付は翌月の同じ日が自動で入ります。金額などを必要に応じて修正して保存

> **注意**：口座振替・カード払いの支出を繰り返し登録した場合、同じ支出の銀行明細やカード明細を取り込んだときに二重計上になります。その明細は **「対象外」** にしてください（[6-4](#6-4-二重計上を防ぐ)）。

### 4-2. 明細の取り込みと仕訳
[6. 銀行・カード明細の取り込み](#6-銀行カード明細の取り込み) の手順で、前月分の明細を取り込み、未処理をゼロにします。

### 4-3. 残高の照合
**帳簿・レポート → 総勘定元帳** で「普通預金」を選び、月末の残高が通帳・ネットバンキングの残高と一致するか確認します。

- 一致しない → 仕訳漏れ・二重計上・金額違いがないか、銀行・カード明細の「未処理」「対象外」を確認します。
- 現金も同様に、手元の事業用現金と照合します。

### 4-4. 領収書の整理
**ホーム** の「やることリスト」に未紐付けの領収書が表示されたら、仕訳と紐付けます（[5-3](#5-3-仕訳との紐付け)）。

## 5. 領収書・請求書の保存

電子帳簿保存法により、**メールやWebで受け取った電子の領収書・請求書は電子のまま保存** する必要があります。紙の領収書もスキャン・撮影して保存しておくと管理が楽です。

### 5-1. アップロード
**領収書・請求書** の枠にファイル（画像・PDF、1件20MBまで）をドラッグ＆ドロップします。かんたん入力の「領収書・請求書」欄から、仕訳と同時に添付することもできます。

### 5-2. 必須の入力項目
アップロード後、一覧の行をクリックして次の項目を入力し **保存** します。

| 項目 | 理由 |
| --- | --- |
| 取引年月日 | 電子帳簿保存法の検索要件 |
| 金額 | 電子帳簿保存法の検索要件 |
| 取引先 | 電子帳簿保存法の検索要件 |
| 書類の種類 | 領収書・請求書・見積書・契約書など |

一覧の上部で、取引日の範囲・金額の範囲・取引先で検索できます。

### 5-3. 仕訳との紐付け
書類の詳細画面に、日付・金額が近い仕訳が **候補** として表示されます。「この仕訳に紐付け」を押すと関連付けられます。

### 5-4. 外部ドライブ（Google ドライブ等）の書類
**領収書・請求書 → 外部ドライブのファイルを紐付け**

共有リンク（https）と取引日・金額・取引先を登録します。この場合、原本は外部ドライブ側で保存されます。**外部ドライブのファイルを削除・移動しない** よう注意してください。

### 5-5. メールで受け取る（設定した場合のみ）
受付用アドレス（例：`receipts@あなたのドメイン`）に領収書メールを転送すると、添付のPDF・画像が自動で保存されます。保存された書類は「メール」ラベルが付き、未紐付けとして表示されるので、取引年月日・金額を確認して紐付けてください。

### 5-6. 削除について
書類を削除しても、ファイルと履歴は保存期間中残ります（一覧からは非表示）。**誤ってアップロードしたもの以外は削除しない** でください。

## 6. 銀行・カード明細の取り込み

### 6-1. CSV で取り込む
1. 銀行・カード会社のWebサイトから、明細をCSV形式でダウンロード
2. **銀行・カード明細** の口座カードの **CSV取込** を押してファイルを選択
3. 列（日付・摘要・入金・出金・金額・残高）が自動判定されます。プレビューで日付・金額が正しいか確認します。
   - 判定がおかしい場合は、各列の割り当てを手動で選び直します。
   - カード明細で「利用額がプラス」の場合は、金額の符号を「プラス＝支払（カード明細）」にします。
4. **〇件を取り込む** を押します。

同じ期間のCSVを重複して取り込んでも、二重登録はされません。列の割り当ては口座ごとに記憶されます。

### 6-2. API で自動取得（GMOあおぞらネット銀行）
口座の **設定** で取得方法を「GMOあおぞらネット銀行 API」にして、「銀行で認可する」から接続します。接続後は毎朝6時（日本時間）に自動で明細を取得します。手動で取得する場合は **API同期** を押します。

### 6-3. 明細を仕訳する
「未処理」タブに、推定した勘定科目付きで明細が並びます。

- 推定が正しければ **仕訳** を押します。
- 違っていれば勘定科目を選び直して **仕訳** を押します（次回から学習されます）。
- 判定できないものは **AIに聞く** で推定させることもできます。
- 学習・ルール・辞書で確度が高い明細は、**確度の高い明細を一括仕訳** でまとめて処理できます。

よく出てくる明細の勘定科目：

| 明細の例 | 選ぶ勘定科目 |
| --- | --- |
| カード会社への引き落とし | **未払金**（カード利用時に計上済みのため） |
| 取引先からの入金（請求済み） | **売掛金** |
| 取引先からの入金（請求していない売上） | 売上高 |
| 生活費の引き出し・私的な支払い | 事業主貸 |
| 自分の個人口座からの入金 | 事業主借 |
| 事業用口座どうしの資金移動 | 移動先の口座の科目（例：普通預金（〇〇銀行）） |

### 6-4. 二重計上を防ぐ
次の明細は **「対象外」** にします（仕訳を作りません）。

- かんたん入力や繰り返し登録で、すでに記帳済みの支出
- 事業と関係のない入出金で、別途記帳が不要なもの

「対象外」タブから「未処理に戻す」こともできます。

## 7. 家事按分

自宅兼事務所の家賃、光熱費、スマホ代など、事業と私生活の両方に使う費用は、**事業で使った割合だけを経費** にします。

### 7-1. 設定
**家事按分**

1. 勘定科目（地代家賃・水道光熱費・通信費など）を選択
2. **事業割合（%）** を入力
3. **按分のタイミング** を選択

   | タイミング | 動き | おすすめの場面 |
   | --- | --- | --- |
   | 決算時にまとめて按分 | 1年間は全額で記帳し、決算整理で私用分を「事業主貸」に振り替える | 基本はこちら |
   | 入力のたびに按分 | 入力時に事業分と私用分（事業主貸）に分けて記帳する | 毎月の経費を正確に見たい場合 |

4. **按分の根拠** を記入（例：「仕事部屋 10㎡ ／ 住居 40㎡ ＝ 25%」「業務での使用時間 1日8時間／16時間 ＝ 50%」）

**按分の根拠は税務調査で説明を求められることがある** ため、必ず記録してください。

### 7-2. 按分割合の目安

| 費用 | 根拠の例 |
| --- | --- |
| 家賃 | 仕事専用スペースの床面積 ÷ 住居全体の床面積 |
| 電気代 | 仕事で使う時間・部屋の割合 |
| 通信費（スマホ・ネット） | 業務での使用時間・使用量の割合 |
| 自動車関連 | 業務での走行距離 ÷ 総走行距離 |

> ガス代・水道代は、飲食業などを除き事業での使用を説明しにくいため、按分しないのが一般的です。

### 7-3. 個人のお金で払った場合
支払方法を「個人のお金」にすると、事業分だけが経費として記帳されます（私用分は記帳しません）。

---

## 8. 固定資産（10万円以上の購入）

### 8-1. 購入時の記帳
10万円以上のパソコン・カメラ・車などを買ったときは、経費ではなく **資産** として記帳します。

例：ノートPC 220,000円を事業用口座で購入
→ かんたん入力で勘定科目に **工具器具備品** を選択（`工具器具備品 / 普通預金`）

### 8-2. 固定資産台帳への登録
**固定資産台帳 → ＋資産を登録**

| 項目 | 入力内容 |
| --- | --- |
| 資産名・勘定科目 | 例：ノートPC／工具器具備品 |
| 取得日・事業供用日 | 使い始めた日が取得日と違う場合のみ事業供用日を入力 |
| 取得価額 | 税込金額 |
| 償却方法・耐用年数 | 下表参照 |
| 事業専用割合 | 私的にも使う場合は事業で使う割合 |

| 取得価額 | 償却方法 |
| --- | --- |
| 10万円未満 | 資産にせず「消耗品費」で経費にする |
| 10万円以上20万円未満 | 一括償却（3年均等）または定額法 |
| 30万円未満（青色申告） | **少額減価償却資産の特例**（購入した年に全額経費。年間合計300万円まで） |
| それ以上 | 定額法（耐用年数は「目安から選ぶ」を参考に） |

主な耐用年数：パソコン4年、サーバー5年、プリンター・複合機5年、カメラ5年、普通自動車（新車）6年、軽自動車（新車）4年、ソフトウェア5年。

減価償却費は年末の決算整理で自動計上されます。

### 8-3. 売却・廃棄したとき
台帳の資産を開き **除却・売却日** を入力します。その年はその月までの減価償却費が計上されます。売却代金や除却損の記帳は振替伝票で行ってください。

---

## 9. 年末の決算整理

12月分の記帳が終わったら（通常は1月中に）、**決算整理** 画面で上から順に実行します。**何度実行しても前回分が置き換わる** ので、仕訳を修正したら再実行して構いません。

### 実行前のチェックリスト
- [ ] 12月までの銀行・カード明細がすべて仕訳済み（「未処理」がゼロ）
- [ ] 通帳・カード明細と、普通預金・未払金の残高が一致
- [ ] 12月中に請求して未入金の売上が「売掛金」で計上されている
- [ ] 12月中に使ったが翌年払いの経費（12月分のカード利用など）が計上されている
- [ ] 固定資産台帳に当年購入の資産が登録されている

### 実行手順

| 順番 | 処理 | 内容 |
| --- | --- | --- |
| ① | 減価償却費の計上 | 固定資産台帳から減価償却仕訳を作成 |
| ② | 家事按分 | 「決算時」に設定した科目の私用分を事業主貸へ振り替え |
| ③ | 期末商品棚卸高 | 在庫がある場合のみ、12/31時点の在庫の仕入金額合計を入力 |
| ④ | 確定申告書類の確認 | 次章を参照 |
| ⑤ | 翌年への繰越 | 申告内容が確定してから実行（[11章](#11-翌年への繰越)） |

---

## 10. 確定申告

### 10-1. 決算書の確認
**確定申告書類 → 青色申告決算書**（白色申告の場合は収支内訳書）

- 売上・経費の各金額に違和感がないか確認します（前年と大きく違う科目は仕訳を見直す）。
- 4ページ目の貸借対照表で、**資産合計と負債・資本合計が一致** していることを確認します。不一致の場合は期首残高を見直します。
- **印刷 / PDF保存** で保存できます。

### 10-2. 所得控除などの入力
**確定申告書類 → 申告書 第一表（所得税）**

| 入力項目 | 金額の確認先 |
| --- | --- |
| 社会保険料控除 | 国民健康保険・国民年金の納付額（控除証明書・納付書） |
| 小規模企業共済等掛金控除 | 小規模企業共済・iDeCoの掛金払込証明書 |
| 生命保険料控除・地震保険料控除 | 保険会社の控除証明書から計算した控除額 |
| 医療費控除 | 医療費の合計 − 保険金等の補填 − 10万円 |
| 寄附金控除 | ふるさと納税の合計 − 2,000円 |
| 配偶者控除・扶養控除・その他 | 該当する場合 |
| 給与所得・雑所得 | 会社員との兼業の場合は源泉徴収票の「給与所得控除後の金額」 |
| 源泉徴収税額 | 取引先から届く支払調書、入金時に差し引かれた源泉税の合計 |
| 予定納税額 | 予定納税をした場合 |

**保存して再計算** を押すと、納める税金（または還付される税金）の概算が表示されます。

> 基礎控除は年分ごとの改正に合わせて自動計算します。最新の改正内容と違う場合は「基礎控除（手入力する場合）」に正しい金額を入力してください。

### 10-3. e-Tax で提出する
1. 国税庁「[確定申告書等作成コーナー](https://www.keisan.nta.go.jp/)」を開き、マイナンバーカード（スマホ読み取り可）でログイン
2. **「決算書・収支内訳書」** を選び、本アプリの青色申告決算書の金額を各ページに転記
3. 続けて **「所得税」** を選び、申告書第一表の各控除額を入力
4. 本アプリの概算と、作成コーナーで計算された税額がほぼ一致することを確認
5. e-Taxで送信（青色申告特別控除65万円の要件）
6. 納付がある場合は3月15日までに納付（振替納税・ダイレクト納付・クレジットカード等）

### 10-4. 消費税の申告（課税事業者のみ）
**確定申告書類 → 消費税** の集計値をもとに、作成コーナーの「消費税」で申告します（期限は3月31日）。

本アプリの集計は概算です。本則課税の場合は、仕入税額控除のためにインボイス（適格請求書）の保存が必要です。

### 10-5. 申告後に保存しておくもの
- 青色申告決算書・申告書の控え（PDF）、e-Taxの受信通知
- **帳簿・レポート** の総勘定元帳・残高試算表（印刷→PDF保存）
- **仕訳帳 → CSV出力** の仕訳データ
- **事業者設定 → データ・連携 → 全データのバックアップ（JSON）**

帳簿と書類の **保存期間は7年**（一部5年）です。

---

## 11. 翌年への繰越

申告内容が確定したら、**決算整理 → ⑤翌年への繰越** を実行します。

- 資産・負債の期末残高が翌年の期首残高になります。
- 元入金は「期首元入金 ＋ 所得 ＋ 事業主借 − 事業主貸」で自動的に再計算されます。
- 期末に在庫がある場合は、翌年1月1日付で「期首商品棚卸高」の仕訳が作られます。
- 実行後に画面右上の年度を翌年に切り替えます。

**繰越後に前年の仕訳を修正した場合は、もう一度繰越を実行** してください（翌年の期首残高が更新されます）。

## 12. システム管理（Cloudflare）

### 12-1. 構成

| 役割 | Cloudflare のサービス | 名前 |
| --- | --- | --- |
| アプリ本体 | Workers | `kaikei` |
| 帳簿データ | D1 | `kaikei-db` |
| 領収書ファイル・自動バックアップ | R2 | `kaikei-receipts` |
| 自動仕訳のAI補助 | Workers AI | — |

ソースコードは GitHub の `shotaro0222/kaikei` で管理されており、設定したブランチに push すると Cloudflare Workers Builds が自動でビルド・デプロイします。

### 12-2. ビルド設定（Workers & Pages → kaikei → 設定 → ビルド）

| 項目 | 値 |
| --- | --- |
| Build command | `npm run build` |
| Deploy command | `npm run deploy:cf`（デプロイとデータベース更新） |
| Root directory | `/` |

### 12-3. シークレット（Workers & Pages → kaikei → 設定 → 変数とシークレット）

| 名前 | 内容 | 注意 |
| --- | --- | --- |
| `APP_PASSWORD` | ログインパスワード | 変更すると即時反映 |
| `SESSION_SECRET` | ログイン状態の署名キー | 変更すると全員ログアウト |
| `ENCRYPTION_KEY` | 銀行APIトークンの暗号化キー | **変更すると銀行API連携の再設定が必要** |
| `GMO_AOZORA_CLIENT_ID` / `GMO_AOZORA_CLIENT_SECRET` | 銀行API（任意） | — |

シークレットの値はパスワードマネージャー等に控えておいてください（Cloudflare 上では再表示できません）。

### 12-4. パスワードを変更する
変数とシークレットで `APP_PASSWORD` を編集して保存します。再デプロイは不要です。

### 12-5. アクセス制限（強く推奨）
帳簿データを守るため、アプリのパスワードに加えて **Cloudflare Access** でアクセスを制限します。

1. Workers & Pages → kaikei → 設定 → ドメインとルート で、`workers.dev` の **Cloudflare Access を有効化**（または Zero Trust → Access → アプリケーションでセルフホスト型アプリとして登録）
2. ポリシーで「Emails」に自分のメールアドレスだけを許可
3. 以後、アプリを開くとメールに届くワンタイムコードの入力が求められます

### 12-6. バックアップ

| 種類 | 方法 | 保存先 |
| --- | --- | --- |
| 自動（毎日6:00 JST） | Cron で全データをJSON出力 | R2 `kaikei-receipts` の `backups/日付.json` |
| 手動 | 事業者設定 → データ・連携 → 全データのバックアップ（JSON） | 自分のPC |
| 仕訳データ | 仕訳帳 → CSV出力 | 自分のPC |
| データベース全体 | D1 の Time Travel（無料プランは過去7日、有料プランは過去30日の任意の時点に復元可能） | Cloudflare |

> 年に一度（申告後）は、手動バックアップとCSVを自分のPCやクラウドストレージにも保存してください。
> 領収書ファイル本体はR2に保存されています。**R2バケット `kaikei-receipts` は絶対に削除しない** でください。

### 12-7. データを復元する
データベースを誤って壊した場合は、D1 の **Time Travel** で過去の時点に戻せます（無料プランは過去7日、有料プランは過去30日以内）。

1. Cloudflare 管理画面 → ストレージとデータベース → D1 → `kaikei-db`
2. 「Time Travel」から戻したい日時を選んで復元
   （コマンドラインの場合：`npx wrangler d1 time-travel restore kaikei-db --timestamp=2026-03-01T00:00:00Z`）

それより前のデータは、R2 の `backups/` のJSONから復元できます。ただし復元用の画面はないため、開発者による作業が必要です。

### 12-8. アプリを更新する
機能追加・修正はブランチに push すると自動でデプロイされます。

- デプロイ状況：Workers & Pages → kaikei → デプロイ（Deployments）
- デプロイに失敗した場合は、ビルドログの最後のエラーを確認します。直前のバージョンが動き続けるので、アプリは止まりません。
- 問題のあるバージョンを戻す場合：デプロイ一覧から以前のバージョンを選んで **ロールバック** します。

データベースの構造変更（`migrations/` フォルダの追加）は、デプロイ時に自動で適用されます。

### 12-9. 費用の目安
個人事業の利用量であれば、ほぼ無料枠内で運用できます。

| サービス | 無料枠の目安 |
| --- | --- |
| Workers | 1日10万リクエスト |
| D1 | 5GB、1日500万行の読み取り |
| R2 | 10GB保存（超過分のみ課金） |
| Workers AI | 1日1万ニューロン（自動仕訳の補助程度なら十分） |

## 13. よくある質問・トラブル対応

### ログイン・表示

| 症状 | 対処 |
| --- | --- |
| 「APP_PASSWORD / SESSION_SECRET が未設定です」と表示される | シークレットを設定する（12-3） |
| パスワードを忘れた | Cloudflare で `APP_PASSWORD` を新しい値に変更する |
| 2週間経つとログアウトされる | 仕様です（セキュリティのため） |
| 画面が古いまま | ブラウザを再読み込み（Ctrl+Shift+R / Cmd+Shift+R） |

### 記帳

| 症状 | 対処 |
| --- | --- |
| 自動仕訳の科目が毎回違う | 正しい科目で登録すれば学習されます。それでも違う場合は「自動仕訳ルール」で優先度を上げたルールを登録 |
| 学習した科目を変えたい | 正しい科目で登録し直すと上書きされます。または自動仕訳ルールで該当の「学習」ルールを編集・削除 |
| 「貸借が一致しません」と表示される | 借方合計と貸方合計を一致させる |

### 明細取込

| 症状 | 対処 |
| --- | --- |
| CSV が文字化けする | Shift_JIS・UTF-8は自動判定されます。それ以外の形式の場合は、Excel等でUTF-8のCSVとして保存し直す |
| 列が自動判定されない | プレビュー画面で、ヘッダ行・日付列・金額列を手動で指定（口座ごとに記憶されます） |
| 入金と出金が逆になる | 「金額の符号」を切り替える |
| 「読み取れない行」がある | 合計行・注記行などは自動でスキップされます。明細行であれば日付形式を確認 |

### 決算・申告

| 症状 | 対処 |
| --- | --- |
| 貸借対照表の貸借が一致しない | 期首残高（事業者設定 → 期首残高）の資産合計と負債・資本合計を一致させる |
| 繰越で「貸借が一致しません」 | 同上。期首残高が不整合です |
| 決算書の任意科目欄が足りない | 7つ目以降の追加科目は自動で「雑費」に合算されます |
| 税額が作成コーナーと違う | 本アプリは概算です。控除の入力漏れがないか確認し、最終的には作成コーナーの計算を正とする |
